Hyperliquid is a Layer 1 built around an on-chain order book. HyperEVM is its EVM execution layer, sharing state with HyperCore, the exchange. This endpoint serves the HyperEVM JSON-RPC API.

Developer docs: [https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm)

Mainnet block explorer: [https://hyperevmscan.io](https://hyperevmscan.io)

### Network Support

| Network             | Full History / Archive                                                                 | HTTPS | WSS |
| ------------------- | -------------------------------------------------------------------------------------- | ----- | --- |
| Hyperliquid Mainnet | <p>HTTPS ❌ (~165 days, latest state only)<br /><br />WSS, Debug and Trace ✅ to genesis</p> | ✅     | ✅   |

> Endpoint URLs end in `/evm`. The URL shown in your dashboard already includes it.

> Two clients answer this endpoint:\
> \- The Hyperliquid node serves the standard JSON-RPC methods with roughly 165 days of block, receipt and log history and **no historical state**: `eth_call`, `eth_getBalance`, `eth_getCode`, `eth_getStorageAt` and `eth_getTransactionCount` return the latest state whatever block parameter you pass. \
> \
> \- Nanoreth, the HyperEVM archive client, serves the Debug API, the Trace API, the filter methods and WebSocket connections, with data back to genesis.

> HyperCore deposits into HyperEVM are not listed in blocks, receipts or logs by the standard methods. \
> \
> Use [eth\_getSystemTxsByBlockNumber](/nodeapi/hyperliquid/hyperevm-api/eth_getsystemtxsbyblocknumber) to read them. \
> \
> Block-level traces (`debug_traceBlockByNumber`, `debug_traceBlockByHash`, `trace_block`, `trace_replayBlockTransactions`) do include the deposit as their first entry, under a hash that differs from the one `eth_getSystemTxsByBlockNumber` reports, so on a deposit block a trace lists one more transaction than the block and its `transactionPosition` values run one ahead of the block's `transactionIndex`.

> `eth_getLogs` is limited to a range of 1,000 blocks per request.

> WebSocket connections are served entirely by nanoreth, so behaviour differs from HTTPS in three ways: the four [HyperEVM API](/nodeapi/hyperliquid/hyperevm-api) methods are not available over WebSocket; `eth_call` and `eth_getBalance` at a past block return historical state over WebSocket; and `eth_call` against HyperCore read precompiles may fail over WebSocket. Use HTTPS for those calls.

> WebSocket clients **MUST** respond to server `ping` frames, otherwise the connection will be closed and re-established every minute.

### Endpoint Capabilities

Hyperliquid endpoints support both HTTP and WebSocket connectivity for production-grade applications.

#### HTTP

Best suited for:

* backend services and APIs
* blockchain data queries
* smart contract deployment and interaction
* development and testing workflows

#### WebSocket

Best suited for:

* real-time transaction monitoring
* event subscriptions
* live dashboards and analytics
* applications that require low-latency data delivery

### Getting Started

To start building on Hyperliquid, connect your application to a Hyperliquid endpoint and send standard Ethereum JSON-RPC requests.

Example request:

<CodeGroup>

```bash title="mainnet"
curl https://mainnet.hyperliquid.validationcloud.io/v1/<YOUR_API_KEY_HERE>/evm \
    -X POST \
    -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":0}'
```

</CodeGroup>
