---
title: "feature"
---

Returns information about amendments the server knows about, including whether they are enabled on the ledger and whether the server knows how to apply them.

This method will use `20` [Compute Units](/nodeapi/about/billing).

***

## Reference: [Here](https://xrpl.org/docs/references/http-websocket-apis/public-api-methods/server-info-methods/feature)

## **Parameters**

* `feature` (string, optional) The unique ID of an amendment, as hexadecimal, or the short name of the amendment. If provided, limits the response to one amendment. Otherwise, the response lists all amendments.

## Returns

* `features` (object) A map of amendment IDs to amendment objects. Each amendment object has `name` (may be omitted), `enabled` (whether the amendment is currently enabled in the latest ledger) and `supported` (whether the server knows how to apply it).
* `ledger_hash`, `ledger_index`, `validated` The ledger version the amendment status was read from.

```json
        "enabled": false,

    "ledger_index": 107292935,
    "validated": true,

  }

```

<CodeGroup>

```bash title="mainnet"
curl https://mainnet.xrpl.validationcloud.io/v1/<YOUR_API_KEY_HERE> \
    -X POST \
    -H "Content-Type: application/json" \
    -d '{"method":"feature","params":[{}]}'
```

</CodeGroup>

Over WebSocket, send `{"id":1,"command":"feature"}` to `wss://mainnet.xrpl.validationcloud.io/v1/<YOUR_API_KEY_HERE>`.

> Without a `feature` filter the full response lists every amendment (roughly 15 KB). The example above is trimmed to the first two entries.
